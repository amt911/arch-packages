# `[amt911]` Arch Repository — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish the four personal Arch packages as a signed pacman repository on GitHub Pages, so `pacman -Syu` updates them with the rest of the system.

**Architecture:** The PKGBUILDs stay in their own repos and enter here as git submodules pinned to a SHA. A GitHub Actions job runs inside an `archlinux:base-devel` container, bootstraps the one AUR build dependency, builds every submodule with `makepkg`, signs the artifacts and the database with a dedicated GPG key, and deploys `public/` to Pages. `runs-on` reads a repo variable so the same workflow runs on a GitHub runner or on the user's mini-PC.

**Tech Stack:** Bash 5, `makepkg`/`repo-add` (pacman 7.1), `namcap`, GnuPG 2.4, GitHub Actions (`checkout@v7`, `configure-pages@v6`, `upload-pages-artifact@v5`, `deploy-pages@v5`), podman for local verification, `shellcheck`.

**Spec:** [`docs/superpowers/specs/2026-09-15-arch-repo-design.md`](../specs/2026-09-15-arch-repo-design.md)

## Global Constraints

- **Repository name: `amt911`.** It is the pacman repo name, the database basename (`amt911.db.tar.zst`) and the public key filename (`amt911.gpg`). Scripts read it from `REPO_NAME`, defaulting to `amt911`.
- **Site URL: `https://amt911.github.io/arch-packages`.** Packages are served from `$SITE_URL/x86_64/`.
- **Architecture directory: `x86_64` only.** All four packages are `arch=('any')`; pacman substitutes `$arch` in the `Server` line.
- **Submodule URLs use HTTPS** (`https://github.com/amt911/….git`), never SSH — the runner clones with the default `GITHUB_TOKEN`.
- **`public/` is never committed.** It is regenerated from scratch on every run.
- **The private GPG key never enters the build user's keyring.** `makepkg` runs unprivileged and unsigned; all signing happens afterwards as root with explicit `--pinentry-mode loopback` and `--passphrase-fd`.
- **Every script is `shellcheck`-clean** with no suppressions unless a comment next to the directive says why.
- **Every script runs as root and drops `makepkg` to `$BUILD_USER`** (default `builder`) — `makepkg` refuses to run as root.
- **Action versions are pinned to a major tag** and kept fresh by Dependabot.
- **Heavy local runs go inside a memory cgroup.** Patching the fonts fans out to `$(nproc)` `fontforge` processes; wrap local builds in `systemd-run --user --scope --quiet -p MemoryHigh=5G -p MemoryMax=6G -p MemorySwapMax=0 -- …`.

### Deviation from the spec, recorded on purpose

The spec listed three scripts and showed `repo-add` inline in the workflow. This plan uses **four**: `build-aur-makedeps.sh`, `build-packages.sh`, `make-repo.sh`, `make-index.sh`. Signing and `repo-add` moved out of the YAML into `make-repo.sh` so the whole pipeline is runnable locally; calling that script `make-index.sh` while it also signs the database would be a lie about what it does.

## Task 2: AUR build-dependency bootstrap

**Files:**
- Create: `aur-makedeps.txt`
- Create: `scripts/build-aur-makedeps.sh`

**Interfaces:**
- Consumes: `packages/*/PKGBUILD` from Task 1 (only to justify the contents).
- Produces: a script invoked as `scripts/build-aur-makedeps.sh`, honouring `BUILD_USER` (default `builder`). Exits 0 with no work when the manifest is missing or empty. Leaves the named packages installed in the container.

**Why this task exists:** `font-patcher` is a `makedepends` of both font packages and is **not in the official repos** (`pacman -Si font-patcher` → *package not found*). `makepkg --syncdeps` resolves official repos only, so without this step half the repository fails to build.

- [ ] **Step 1: Write the manifest**

```bash
cat > aur-makedeps.txt <<'EOF'
# Build-only dependencies that live in the AUR, one per line.
#
# `makepkg --syncdeps` resolves the official repositories and nothing else, so
# anything here has to be built from the AUR before the packages that need it.
# These are installed into the build container and deliberately NOT published:
# [amt911] serves this repo's own packages, not other people's.

# makedepends of ttf-atkinson-hyperlegible-next-nerd{,-mono}-git
font-patcher
EOF
```

- [ ] **Step 2: Write the script**

```bash
cat > scripts/build-aur-makedeps.sh <<'SCRIPT'
#!/usr/bin/env bash
#
# Builds and installs the AUR packages listed in aur-makedeps.txt.
#
# These are build dependencies of our own packages, not products of this repo:
# they are installed into the throwaway build container and never copied into
# public/. Keeping someone else's package in [amt911] would be recurring
# maintenance nobody asked for.
set -euo pipefail

REPO_ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
MANIFEST=${MANIFEST:-$REPO_ROOT/aur-makedeps.txt}
BUILD_USER=${BUILD_USER:-builder}

if [[ $EUID -ne 0 ]]; then
    echo "error: must run as root; makepkg is dropped to '$BUILD_USER'" >&2
    exit 1
fi

if [[ ! -f $MANIFEST ]]; then
    echo "==> no $MANIFEST, nothing to bootstrap"
    exit 0
fi

workdir=$(mktemp -d)
# The build user has to be able to traverse into it.
chmod 755 "$workdir"
trap 'rm -rf "$workdir"' EXIT

while IFS= read -r line; do
    pkg=${line%%#*}                 # strip comments
    pkg=${pkg//[[:space:]]/}        # strip all whitespace
    [[ -n $pkg ]] || continue

    if pacman -Qq "$pkg" &>/dev/null; then
        echo "==> $pkg already installed, skipping"
        continue
    fi

    echo "==> building AUR build-dependency: $pkg"
    git clone --depth 1 "https://aur.archlinux.org/${pkg}.git" "$workdir/$pkg"
    chown -R "$BUILD_USER:$BUILD_USER" "$workdir/$pkg"
    ( cd "$workdir/$pkg" && sudo -u "$BUILD_USER" makepkg --syncdeps --noconfirm --clean )
    pacman -U --noconfirm "$workdir/$pkg"/*.pkg.tar.*
done < "$MANIFEST"

echo "==> AUR build-dependencies ready"
SCRIPT
chmod +x scripts/build-aur-makedeps.sh
```

## Task 3: Package build script

**Files:**
- Create: `scripts/build-packages.sh`

**Interfaces:**
- Consumes: `packages/*/PKGBUILD` (Task 1), the AUR dependencies installed by Task 2.
- Produces: `public/x86_64/*.pkg.tar.zst`, **unsigned**. Environment: `BUILD_USER` (default `builder`), `OUT` (default `$REPO_ROOT/public/x86_64`). Task 4 consumes exactly that glob.

- [ ] **Step 1: Write the script**

```bash
cat > scripts/build-packages.sh <<'SCRIPT'
#!/usr/bin/env bash
#
# Builds every PKGBUILD under packages/ into public/x86_64/.
#
# Deliberately does NOT sign: the private key never enters the unprivileged
# build user's keyring. scripts/make-repo.sh signs afterwards, as root, with
# explicit loopback flags — see the comment there.
set -euo pipefail

REPO_ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
BUILD_USER=${BUILD_USER:-builder}
OUT=${OUT:-$REPO_ROOT/public/x86_64}

if [[ $EUID -ne 0 ]]; then
    echo "error: must run as root; makepkg is dropped to '$BUILD_USER'" >&2
    exit 1
fi

if ! id -u "$BUILD_USER" &>/dev/null; then
    echo "error: build user '$BUILD_USER' does not exist" >&2
    exit 1
fi

# The published repository holds the current version of each package and
# nothing else, so the output tree is rebuilt from scratch every run.
rm -rf "$OUT"
install -d -m 755 "$OUT"

built=0
for pkgdir in "$REPO_ROOT"/packages/*/; do
    [[ -f ${pkgdir}PKGBUILD ]] || continue
    built=$((built + 1))
    printf '\n==> building %s\n' "$(basename "${pkgdir%/}")"

    chown -R "$BUILD_USER:$BUILD_USER" "$pkgdir"

    # --cleanbuild re-extracts the sources, which is what makes a -git package's
    # pkgver() see today's upstream HEAD instead of a stale checkout.
    # --clean drops src/ and pkg/ afterwards so the submodule tree stays clean.
    ( cd "$pkgdir" && sudo -u "$BUILD_USER" \
        makepkg --syncdeps --noconfirm --cleanbuild --clean --force )

    # Advisory only: namcap reports packaging smells, not build failures.
    if command -v namcap >/dev/null; then
        namcap "${pkgdir}PKGBUILD" "$pkgdir"*.pkg.tar.zst || true
    fi

    mv -v "$pkgdir"*.pkg.tar.zst "$OUT/"
done

if (( built == 0 )); then
    echo "error: no PKGBUILD under packages/ — are the submodules initialised?" >&2
    exit 1
fi

shopt -s nullglob
packages=("$OUT"/*.pkg.tar.zst)
if (( ${#packages[@]} == 0 )); then
    echo "error: built $built PKGBUILD(s) but no package landed in $OUT" >&2
    exit 1
fi

printf '\n==> %d package(s) in %s\n' "${#packages[@]}" "$OUT"
printf '    %s\n' "${packages[@]##*/}"
SCRIPT
chmod +x scripts/build-packages.sh
```

**Mount the repo read-only and copy it in.** A read-write bind mount would let the container's `chown -R builder` rewrite ownership on the host tree through the rootless user namespace, leaving files owned by an unmapped subuid that the user then cannot delete without `podman unshare`.

```bash

    pacman -Syu --noconfirm --needed git namcap
    useradd -m builder
    printf "builder ALL=(ALL) NOPASSWD: /usr/bin/pacman\n" > /etc/sudoers.d/builder
    chmod 440 /etc/sudoers.d/builder
```

## Task 4: Signing and repository database

**Files:**
- Create: `scripts/make-repo.sh`

**Interfaces:**
- Consumes: `public/x86_64/*.pkg.tar.zst` from Task 3.
- Produces: `public/x86_64/amt911.{db,files}{,.tar.zst}` plus `.sig` for each package and database, and `public/amt911.gpg`. Environment: `REPO_NAME` (default `amt911`), `PUBLIC` (default `$REPO_ROOT/public`), `SIGN_KEY` (fingerprint; **unset = build unsigned**, for local debugging), `GPG_PASSPHRASE`.

**Why signing is explicit rather than `makepkg --sign` + gpg-agent:** every `gpg` call here passes `--pinentry-mode loopback` and reads the passphrase from a file descriptor. Nothing depends on an agent being warm from a previous call, and the passphrase never appears in `ps`. `repo-add --sign` would call `gpg` itself, without those flags, and hang or fail depending on agent state.

- [ ] **Step 1: Write the script**

```bash
cat > scripts/make-repo.sh <<'SCRIPT'
#!/usr/bin/env bash
#
# Signs the built packages, assembles the pacman database, signs it, and
# exports the public key next to the repository.
#
# Signing is explicit rather than delegated to `makepkg --sign` or
# `repo-add --sign`: every gpg call below passes --pinentry-mode loopback and
# reads the passphrase from a file descriptor, so nothing depends on gpg-agent
# holding a cached passphrase from an earlier call, and the passphrase never
# reaches the process table.
set -euo pipefail

REPO_ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
REPO_NAME=${REPO_NAME:-amt911}
PUBLIC=${PUBLIC:-$REPO_ROOT/public}
OUT=$PUBLIC/x86_64
# Unset => unsigned repository. Local debugging only; CI always sets both.
SIGN_KEY=${SIGN_KEY:-}
GPG_PASSPHRASE=${GPG_PASSPHRASE:-}

shopt -s nullglob
packages=("$OUT"/*.pkg.tar.zst)
if (( ${#packages[@]} == 0 )); then
    echo "error: no packages in $OUT — run scripts/build-packages.sh first" >&2
    exit 1
fi

gpg_sign() {   # gpg_sign <file>  =>  <file>.sig
    gpg --batch --yes --detach-sign --no-armor \
        --pinentry-mode loopback --passphrase-fd 3 \
        --local-user "$SIGN_KEY" --output "$1.sig" "$1" 3<<<"$GPG_PASSPHRASE"
}

if [[ -n $SIGN_KEY ]]; then
    for pkg in "${packages[@]}"; do
        echo "==> signing ${pkg##*/}"
        gpg_sign "$pkg"
    done
else
    echo "==> SIGN_KEY unset: building an UNSIGNED repository (debug only)"
fi

# repo-add appends; the database is rebuilt from scratch so a removed package
# actually disappears instead of lingering as an unresolvable entry.
rm -f "$OUT/$REPO_NAME".db* "$OUT/$REPO_NAME".files*
repo-add "$OUT/$REPO_NAME.db.tar.zst" "${packages[@]}"

if [[ -n $SIGN_KEY ]]; then
    for db in "$OUT/$REPO_NAME.db.tar.zst" "$OUT/$REPO_NAME.files.tar.zst"; do
        echo "==> signing ${db##*/}"
        gpg_sign "$db"
    done

    # pacman fetches <repo>.db.sig, not <repo>.db.tar.zst.sig. repo-add makes
    # exactly this kind of symlink for the databases themselves; mirror it for
    # the signatures. actions/upload-pages-artifact tars with --dereference, so
    # all four land on Pages as real files.
    ln -sf "$REPO_NAME.db.tar.zst.sig"    "$OUT/$REPO_NAME.db.sig"
    ln -sf "$REPO_NAME.files.tar.zst.sig" "$OUT/$REPO_NAME.files.sig"

    # Served so a new machine can `pacman-key --add` it. Public half only.
    gpg --armor --export "$SIGN_KEY" > "$PUBLIC/$REPO_NAME.gpg"
    echo "==> exported public key to $PUBLIC/$REPO_NAME.gpg"
fi

echo "==> repository ready in $OUT"
SCRIPT
chmod +x scripts/make-repo.sh
```

## Task 5: Landing page

**Files:**
- Create: `scripts/make-index.sh`

**Interfaces:**
- Consumes: `public/x86_64/*.pkg.tar.zst` (Task 3) and, when present, `public/amt911.gpg` (Task 4).
- Produces: `public/index.html`. Environment: `REPO_NAME`, `PUBLIC`, `SITE_URL` (default `https://amt911.github.io/arch-packages`), `SIGN_KEY` (only to print the fingerprint on the page).

The page exists so that opening the repository URL tells you how to use it. Every value on it is read from the artifacts, so it cannot drift from what was actually published.

- [ ] **Step 1: Write the script**

```bash
cat > scripts/make-index.sh <<'SCRIPT'
#!/usr/bin/env bash
#
# Renders public/index.html from the packages that were actually built, so the
# page cannot drift from what is published.
set -euo pipefail

REPO_ROOT=$(cd "$(dirname "${BASH_SOURCE[0]}")/.." && pwd)
```

- [ ] **Step 1: Write the workflow**

```bash
mkdir -p .github/workflows
cat > .github/workflows/repo.yml <<'YAML'
name: repo

# No `pull_request` trigger, on purpose. This workflow may run on a
# self-hosted runner on the maintainer's own hardware (see
# docs/self-hosted-runner.md); a fork PR must never be able to execute code
# there. Only pushes to main, the schedule, and a manual dispatch build.
on:
  push:
    branches: [main]
    paths:
      - 'packages/**'
      - 'aur-makedeps.txt'
      - 'scripts/**'
      - '.github/workflows/repo.yml'
  schedule:
    # Both font packages are -git: their pkgver() follows upstream HEAD, so
    # without a scheduled rebuild they freeze at whatever the last manual push
    # produced. 04:00 UTC keeps it off the top of the hour.
    - cron: '0 4 * * *'
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

# Two Pages deployments would clobber each other. Queue instead of cancelling:
# every run produces the complete repository, so a cancelled one wastes a full
# font-patching build.
concurrency:
  group: pages
  cancel-in-progress: false

jobs:
  build:
    # Repo variable, so switching to the mini-PC is a Settings change rather
    # than a workflow edit — and switching back is just as fast when it is off.
    runs-on: ${{ vars.BUILD_RUNNER || 'ubuntu-latest' }}
    # Kept even on self-hosted: identical build in both places, and the host
    # never accumulates makedepends (fontforge, toolchains) run after run.
    container:
      image: archlinux:base-devel
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}

    steps:
      - name: Install build tooling
        run: |
          pacman -Syu --noconfirm --needed git namcap
          git config --global --add safe.directory '*'

      - uses: actions/checkout@v7
        with:
          submodules: recursive

      - name: Create the build user
        run: |
          useradd -m builder
          printf 'builder ALL=(ALL) NOPASSWD: /usr/bin/pacman\n' > /etc/sudoers.d/builder
          chmod 440 /etc/sudoers.d/builder

      - name: Import the signing key
        env:
          GPG_PRIVATE_KEY: ${{ secrets.GPG_PRIVATE_KEY }}
        run: |
          if [ -z "$GPG_PRIVATE_KEY" ]; then
            echo "::error::secret GPG_PRIVATE_KEY is empty — see docs/signing.md."
            echo "::error::Refusing to publish unsigned: consumers use SigLevel = Required."
            exit 1
          fi
          printf '%s' "$GPG_PRIVATE_KEY" | gpg --batch --import
          fpr=$(gpg --list-secret-keys --with-colons | awk -F: '/^fpr:/ {print $10; exit}')
          echo "SIGN_KEY=$fpr" >> "$GITHUB_ENV"
          echo "Imported $fpr"

      - name: Bootstrap AUR build-dependencies
        run: ./scripts/build-aur-makedeps.sh

      - name: Build packages
        run: ./scripts/build-packages.sh

      - name: Sign and assemble the repository
        env:
          GPG_PASSPHRASE: ${{ secrets.GPG_PASSPHRASE }}
        run: ./scripts/make-repo.sh

      # Must precede the landing page: it is what defines steps.pages.outputs.
      - uses: actions/configure-pages@v6
        id: pages

      - name: Render the landing page
        env:
          SITE_URL: ${{ steps.pages.outputs.base_url || 'https://amt911.github.io/arch-packages' }}
        run: ./scripts/make-index.sh

      - uses: actions/upload-pages-artifact@v5
        with:
          # Tars with --dereference, which is what turns repo-add's
          # <repo>.db / <repo>.db.sig symlinks into the real files Pages needs.
          path: public

      - uses: actions/deploy-pages@v5
        id: deployment
YAML
```

- [ ] **Step 1: Write the guide**

Write `docs/signing.md` in Spanish (matching the user's other docs), covering, in this order and with the exact commands:

1. **Why a dedicated key** — this key's only job is signing `[amt911]`; it is not the user's git-signing or personal key, so it can be rotated without touching anything else.
2. **Generate it:**

   ```bash
   gpg --full-generate-key
   # (1) RSA and RSA · 4096 · 0 = does not expire
   # Real name: amt911 Arch Repository
   # Email:     a.merlo.truji10@gmail.com
   # Comment:   package signing
   ```

3. **Get the fingerprint:**

   ```bash
   gpg --list-secret-keys --keyid-format=long --with-colons \
     | awk -F: '/^fpr:/ {print $10; exit}'
   ```

4. **Export and load the secrets:**

   ```bash
   gpg --armor --export-secret-keys <FINGERPRINT> > /tmp/amt911-signing.asc
   gh secret set GPG_PRIVATE_KEY --repo amt911/arch-packages < /tmp/amt911-signing.asc
   gh secret set GPG_PASSPHRASE --repo amt911/arch-packages
   shred -u /tmp/amt911-signing.asc
   ```

5. **A warning block:** the private key must never be committed, never pasted into an issue, and the exported file must be shredded. `.gitignore` does not protect against `git add -f`.
6. **Back it up** — `gpg --export-secret-keys` to an offline medium plus a revocation certificate (`gpg --gen-revoke`), because losing it means every machine has to re-trust a new key by hand.
7. **Rotation** — generate the new key, load the new secrets, run the workflow, then on every machine: `pacman-key --delete <OLD>`, `pacman-key --add` the new one, `pacman-key --lsign-key`. Note explicitly that a rotation is a manual visit to every machine, which is why the key is generated without an expiry date.
8. **Verify it worked** — after the first successful run, `curl -I https://amt911.github.io/arch-packages/x86_64/amt911.db.sig` returns `200`.
